## 本题考点

### 一、基本语法与表达式
- **整数除法与类型转换**：`int / int` 结果为截断整数，赋值给 `double` 时发生隐式类型提升变为浮点数（如 `2.0`）。
- **逻辑运算符短路机制**：`&&` 左侧为假时右侧直接跳过不执行；`||` 左侧为真时右侧跳过。
- **运算符优先级与结合性**：后置自增 `++` 优先级高于解引用 `*`，且后置递增先参与运算再自增。
- **switch 语法规范**：`case` 标签必须是整型常量表达式或字符常量，不允许浮点数和变量。

### 二、内存模型与结构体
- **结构体内存对齐（Memory Alignment）**：结构体大小通常大于所有成员大小简单相加，存在对齐边界和 Padding 填充字节。
- **预处理与宏替换**：宏是预处理阶段的无类型纯文本替换，无独立内存分配，不求值，不同于函数调用。

### 三、指针与字符串
- **转义字符识别规则**：`\0` 后跟 1~2 位数字会被贪婪解析为八进制字符（如 `\045` 实际是字符 `%`），而非字符串结束符 `\0`。
- **strcpy 复制行为**：`strcpy` 会将源字符串的结束符 `\0` 完整拷贝到目标缓冲区，导致目标串后续字符被截断。
- **指针相减意义**：两同类型指针相减表示元素间隔个数（`ptrdiff_t`），并非物理字节数。

#### 错题 4：整数除法运算结果的类型提升

**【原题】**
> 设有声明 `int a = 5, b = 2; double c = a / b;`，则变量 `c` 的值是？
> - [ ] A. 2.5
> - [ ] B. 2.0
> - [x] C. 2
> - [ ] D. 编译错误

- **你的答案**：C（`2`）
- **正确答案**：B（`2.0`）
- **表现**：误选了整型 `2`，忽略了目标变量 `double c` 的类型。
- **原因分析**：
  1. **右侧求值**：`int a = 5, b = 2;`，执行 `a / b` 时两边都是 `int`，确实按照整数截断除法计算，得到整数 `2`（没有保留小数 `.5`，这点记忆完全正确）。
  2. **左侧赋值与类型提升**：计算出的结果被赋值给 `double c`。浮点数在内存中按 IEEE 754 格式存储，C 语言自动执行隐式类型提升，将整数 `2` 转换为浮点数 `2.0` 存入变量 `c`。
  3. **选项辨析**：选项 C 的 `2` 代表整型常量，选项 B 的 `2.0` 代表浮点数值。题干问的是 `double c` 的最终值，因此是浮点数 `2.0`。
- **正确做法**：区分“右侧表达式计算过程（按 int 除法算得 2）”与“赋值给左侧变量后的类型形态（double 存储为 2.0）”。

#### 错题 7：转义字符与字符串截断陷阱

**【原题】**
> 设有定义：
> ```c
> char s[] = "123\0456\0abc";
> ```
> 则 `strlen(s)` 和 `sizeof(s)` 的返回值分别是？
> - [x] A. 3 和 12
> - [ ] B. 6 和 12
> - [ ] C. 6 和 11
> - [ ] D. 3 和 11

- **你的答案**：A（`3 和 12`）
- **正确解析**：`strlen(s) = 5`，`sizeof(s) = 10`（原卷选项存在笔误）
- **表现**：看到 `\0` 便认为字符串在第 3 个字符后立即终止。
- **原因分析**：
  在 C 语言字符串中，`\` 引导转义字符：
  - `\0` 后面紧跟数字 `45` 时，编译器会根据八进制转义规则贪婪匹配最多 3 位八进制数字，因此 `\045` 被解析为一个八进制 ASCII 字符（八进制 45 = 十进制 37，对应字符 `%`）。
  - 字符串实际字符序列为：`'1'`, `'2'`, `'3'`, `'\045'`(即'%'), `'6'`, `'\0'`, `'a'`, `'b'`, `'c'`, `'\0'`。
  - `strlen` 遇到第二个真正的 `\0` 终止，计数为 5（`'1'`, `'2'`, `'3'`, `'%'`, `'6'`）。
  - `sizeof` 计算包含末尾隐藏 `\0` 的总字节数，共 10 字节。
- **正确做法**：牢记转义字符规则，遇到 `\0` 必须检查其后是否跟随 `0-7` 数字，避免被假“结束符”误导。

#### 错题 8：宏替换与函数本质区别

**【原题】**
> 针对宏定义与函数，下列叙述中正确的是？
> - [ ] A. 宏定义 `#define SQR(x) x*x` 在计算 `SQR(1 + 2)` 时结果为 9
> - [ ] B. 宏替换是在编译时的语法分析阶段进行的，具有类型检查机制
> - [ ] C. 宏替换只是纯粹的文本替换，不分配内存空间，也不求值
> - [x] D. 带参数的宏与函数的执行效率相同，只是写法更简练

- **你的答案**：D（带参数的宏与函数的执行效率相同，只是写法更简练）
- **正确答案**：C（宏替换只是纯粹的文本替换，不分配内存空间，也不求值）
- **表现**：误认为宏与函数仅是写法风格差异。
- **原因分析**：
  1. 宏替换发生在编译预处理阶段，编译器直接在代码中展开文本，不生成函数栈帧，没有压栈出栈开销。
  2. 宏不进行类型检查，不分配内存，求值必须等待编译器后续解析，若括号不规范极易引发逻辑错误（如 `SQR(1+2)` 展开为 `1+2*1+2 = 5`）。
- **正确做法**：记住宏的本质是“文本替换”，函数是“带类型检查和栈调用的代码段”。

#### 错题 9：后置自增与指针解引用结合

**【原题】**
> 若有定义 `int arr[5] = {10, 20, 30, 40, 50}; int *ptr = arr;`，则表达式 `*ptr++` 与 `(*ptr)++` 的区别是？
> - [ ] A. 无区别，两者都先取值再让指针指向下一个位置
> - [ ] B. `*ptr++` 返回当前值并将指针后移一位；`(*ptr)++` 返回当前值并将当前内存处的值自增 1
> - [x] C. `*ptr++` 使指针先自增一位再解引用；`(*ptr)++` 使元素值先加 1 再返回
> - [ ] D. 两者都会导致语法报错，因为 `++` 无法与 `*` 结合

- **你的答案**：C（`*ptr++` 使指针先自增一位再解引用）
- **正确答案**：B（`*ptr++` 返回当前值并将指针后移一位；`(*ptr)++` 返回当前值并将当前内存处的值自增 1）
- **表现**：混淆了后置自增的求值时机和指针与数值的作用对象。
- **原因分析**：
  - 后缀 `++` 的共同铁律是：**先返回当前变量未递增时的值，随后变量自身加 1**。
  - `*ptr++`：等价于 `*(ptr++)`。返回当前 `*ptr` 的值，随后指针 `ptr` 本身后移 1 个单位。
  - `(*ptr)++`：先取当前指针指向的值，随后使该内存处的值加 1。
- **正确做法**：前缀自增“先变后用”，后缀自增“先用后变”。

#### 错题 14：strcpy 写入的终止符截断

**【原题】**
> 执行下列语句后，字符串 `str` 的内容是？
> ```c
> char str[20] = "Hello";
> strcpy(str + 2, "abc");
> ```
> - [ ] A. `"Heabc"`
> - [ ] B. `"Helloabc"`
> - [x] C. `"Heabco"`
> - [ ] D. `"abc"`

- **你的答案**：C（`"Heabco"`）
- **正确答案**：A（`"Heabc"`）
- **表现**：认为 `strcpy` 只拷贝了 3 个可见字符 `'a'`, `'b'`, `'c'`，保留了原字符串后面的 `'o'`。
- **原因分析**：
  `strcpy(dest, src)` 会完整拷贝源字符串的所有字符**以及末尾的 `\0`**。
  - 原数组：`['H', 'e', 'l', 'l', 'o', '\0']`
  - `strcpy(str + 2, "abc")` 从下标 2 开始写入：
    - `str[2] = 'a'`
    - `str[3] = 'b'`
    - `str[4] = 'c'`
    - `str[5] = '\0'`（把原先的 `'o'` 覆盖成了 `'\0'`）
  - 打印 `str` 时在下标 5 遇到 `\0` 立即终止，输出为 `"Heabc"`。
- **正确做法**：牢记字符串库函数（如 `strcpy`、`sprintf`）写入目标时必定会自动追加 `\0`。

#### 错题 15：短路求值（Short-circuit Evaluation）

**【原题】**
> 以下程序片段的输出结果是？
> ```c
> int a = 0, b = 2;
> if (a++ && ++b) {
>     b += 10;
> }
> printf("a = %d, b = %d\n", a, b);
> ```
> - [ ] A. `a = 1, b = 2`
> - [ ] B. `a = 1, b = 3`
> - [x] C. `a = 0, b = 2`
> - [ ] D. `a = 1, b = 13`

- **你的答案**：C（`a = 0, b = 2`）
- **正确答案**：A（`a = 1, b = 2`）
- **表现**：误以为短路会导致 `a++` 也不生效。
- **原因分析**：
  表达式为 `if (a++ && ++b)`，其中 `a = 0, b = 2`：
  1. 先计算左操作数 `a++`：后置递增先取原值 `0` 参与逻辑运算，条件为假；随后 `a` 完成自增变为 `1`。
  2. 逻辑与 `&&` 规则：只要左操作数为假，整个表达式已确定为假，右操作数 `++b` **被完全短路跳过，根本不执行**。
  3. 最终状态：`a` 变成了 `1`，`b` 仍然保持 `2`。
- **正确做法**：短路发生仅跳过右侧未执行的表达式，左侧已求值的递增/副作用依然有效。

### 二、判断题错题分析

#### 错题 3：switch-case 的常量要求

**【原题】**
> 在 switch 语句中，`case` 后的表达式必须是整型常量表达式或字符常量，不能是浮点常量或变量。
> - [ ] 正确 (T)
> - [x] 错误 (F)

- **你的判断**：错误 (F)
- **正确判断**：正确 (T)
- **表现**：误以为 case 可以使用浮点数或变量。
- **原因分析**：C 语言底层 `switch` 通常会生成跳转表（Jump Table），因此标准明确强制：`case` 后的表达式必须是整型常量表达式（包括 `int`、`char`、`enum`），不能使用浮点数（如 `case 1.5:` 无法通过编译）或变量。
- **正确做法**：遇到 `switch`，时刻警惕 `case` 的“整型常量”限制。

#### 错题 8：结构体内存对齐

**【原题】**
> 结构体变量所占用的内存空间大小一定精确等于其所有成员变量类型大小的简单算术相加。
> - [x] 正确 (T)
> - [ ] 错误 (F)

- **你的判断**：正确 (T)
- **正确判断**：错误 (F)
- **表现**：误以为结构体大小等于各成员大小直接相加。
- **原因分析**：
  CPU 为了提高总线访问内存效率，强制要求数据按照类型大小的整数倍对齐（内存对齐）。
  例如：
  ```c
  struct Node {
      char a;    // 1 字节 + 3 字节填充 (Padding)
      int b;     // 4 字节
  };
  ```
  `sizeof(struct Node)` 是 8 字节，而不是 1 + 4 = 5 字节。
- **正确做法**：牢记结构体存在内存对齐和 Padding 填充，`sizeof(struct)` 通常大于成员大小之和。

## 关键知识点总结与提分策略

1. **短路求值副作用边界**：
   - `a++ && b++`：左边 `a++` 必定求值并产生自增副作用；仅当左边为假时，右边 `b++` 彻底不执行。
2. **字符串操作底层安全**：
   - 任何带 `str` 的字符串操作，必须主动追踪 `\0` 的去向。`strcpy` 写入会强制携带 `\0`，会覆盖后续位置。
3. **结构体与内存布局**：
   - 结构体内存对齐规则是转专业面试和笔试的高频考点，务必掌握自然对齐原则。
4. **指针后缀运算优先级**：
   - `*p++` 与 `(*p)++` 是分水岭考题，重点看括号将 `++` 绑定给指针还是绑定给解引用的值。
