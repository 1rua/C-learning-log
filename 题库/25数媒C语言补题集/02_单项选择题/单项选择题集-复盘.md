## 本题考点

### 一、类型与溢出
- `short` 16 位有符号范围：-32768 ~ 32767
- 超出范围时的截断：减 65536（2^16）回绕
- `long` 也会溢出，溢出后符号改变导致循环终止

### 二、运算符与表达式
- 运算符优先级：算术 > 关系 > 逻辑 > 赋值
- 赋值表达式 `i=j=10` 的值是 10（非 0 为真），与 `==` 的区别

### 三、流程控制
- `switch` 的 fall-through（穿透）：缺 `break` 会贯穿后续 case
- `while(i--)` 后置自减：先判断后减 1
- `continue` 跳过本轮循环剩余部分

## 错误记录

### 一、流程控制

#### 错题 2-4：switch 穿透（fall-through）
- **用户答案**：D（a=2,b=2）
- **正确答案**：A（a=2,b=1）
- **表现**：以为 `b++` 在 `case 2` 中执行了两次
- **原因**：`x=1` 匹配 `case 1`，执行 `a++`（a=1），因为没有 `break`，穿透到 `case 2`，执行 `a++; b++;`（a=2, b=1）。`b` 只在 `case 2` 中加了一次，`case 0` 没匹配到所以 `b++` 没执行
- **正确做法**：逐行追踪：`case 0` 不匹配跳过 → `case 1` 匹配 `a++` → 穿透 `case 2` 执行 `a++, b++` → 最终 a=2, b=1

#### 错题 2-6：while(i--) + continue 累加
- **用户答案**：C（9）
- **正确答案**：D（6）
- **表现**：`while(i--)` 中 `i` 的变化时机判断错误
- **原因**：`while(i--)` 是后置自减，**先用 i 的旧值判断循环条件，再减 1**。循环体内 `i` 的取值范围是 4, 3, 2, 1, 0（不是 5, 4, 3, 2, 1）。偶数累加：4+2+0=6
- **正确做法**：逐轮推演：

| 轮次 | 判断时的 i | 进入循环体时的 i | i%2 | s 变化 |
|:---:|:---:|:---:|:---:|:---:|
| 1 | 5(真) | 4 | 0 | s+=4=4 |
| 2 | 4(真) | 3 | 1 | continue |
| 3 | 3(真) | 2 | 0 | s+=2=6 |
| 4 | 2(真) | 1 | 1 | continue |
| 5 | 1(真) | 0 | 0 | s+=0=6 |
| 6 | 0(假) | — | — | 退出 |

#### 错题 2-9：for 循环条件中赋值 = 等于 == 陷阱
- **用户答案**：A（语法错误，不能执行）
- **正确答案**：B（无限次）
- **表现**：以为 `i=j=10` 是语法错误
- **原因**：`i=j=10` 是合法的赋值表达式，从右向左：`j=10`（值为 10），再 `i=10`（值为 10）。整个表达式值为 10，非 0，永远为真 → 死循环。**如果题目是 `i=j==10` 才是关系判断**
- **正确做法**：区分 `=`（赋值，值是被赋的值）和 `==`（相等判断，值是 0 或 1）。`for` 的条件部分只要是合法表达式就行，不要求一定是 `==`

### 二、询问（不确定但答对）

#### 询问 2-1：short 溢出截断计算
- **用户答案**：B（-32759）✅
- **问题**："经过 short 之后会怎么样"、"考试要怎么算"
- **知识点**：`short` 范围 -32768 ~ 32767。32777 超出上限，**减 65536 回绕**：32777 - 65536 = -32759
- **考场速算口诀**：超上限 → 减 65536；超下限 → 加 65536

#### 询问 2-2：运算符优先级
- **用户答案**：C（%）✅
- **问题**："运算符优先级"
- **知识点**：优先级从高到低：算术(%) > 关系(<=) > 逻辑(&&) > 赋值(=)
- **考场口诀**："算 > 关 > 逻 > 赋"

#### 询问 2-10：long 溢出与死循环
- **用户答案**：未作答
- **正确答案**：B（循环条件永为真，循环无限次）
- **问题**："long 和 \t 是什么"
- **知识点**：
  - `long`：长整型，范围比 `int` 大但仍然有限
  - `\t`：制表符（Tab），转义字符
  - 本题 `num` 从 1 开始自增，`while(num++ > 0)` 中 `num++` 始终返回正值（即使溢出，后置自增返回的是溢出前的正值），外层循环永不终止，程序无限打印

## 关键知识点总结

1. **short 溢出**：范围 -32768~32767，超限减 65536 回绕
2. **运算符优先级**：算 > 关 > 逻 > 赋
3. **switch fall-through**：缺 `break` 会贯穿后续所有 case，这是合法行为而非编译错误
4. **while(i--)**：后置自减，先判断再减 1，循环体内 i 已经减过了
5. **`=` vs `==`**：赋值表达式的值是被赋的值，可以放在条件中；`=` 不是语法错误，但几乎总是逻辑错误
6. **long 溢出**：`long` 也有上限，`num++` 后置自增返回旧值，即使溢出后 num 变负，返回的仍是溢出前的正值

## 未掌握知识点分析

### 🔴 严重薄弱：`++` / `--` 的前置与后置

**暴露问题：** 疑惑 3（`i--` 为什么是循环条件）

**分析：** 用户把 `i--` 当成一个"操作"，没意识到它也是一个**有返回值的表达式**。这是 C 语言和 Python 的核心差异之一——Python 的 `i -= 1` 是语句，没有返回值；C 的 `i--` 是表达式，有值。

**需要补的：**

| 写法 | 返回值 | 副作用 |
|------|--------|--------|
| `i++` | i 的**旧**值 | i 加 1 |
| `++i` | i 的**新**值 | i 加 1 |
| `i--` | i 的**旧**值 | i 减 1 |
| `--i` | i 的**新**值 | i 减 1 |

**口诀：** 符号在前 → 先变后用；符号在后 → 先用后变。

**建议练习：** 找几道只有 `i++` / `++i` / `i--` / `--i` 的题，逐轮手算，直到能脱口而出。

---

### 🔴 严重薄弱：`switch-case` 执行机制

**暴露问题：** 疑惑 5、6（为什么 case 0 没执行、怎么看匹配）

**分析：** 用户把 `switch` 理解成了 `if-else if-else` 的语法糖，以为每个 case 都会被"判断"一遍。实际上 switch 是**跳转表**：先算值，直接跳到匹配位置，然后一路向下。

**正确心智模型：**

```
switch 不是"逐条判断"，是"直接跳过去"
```

```
if-else 模型（错误）:          switch 模型（正确）:
  判断 case 0？否               算出值 = 1
  判断 case 1？是，执行          跳到 case 1
  判断 case 2？是，执行          ↓ 一路穿透
  ...                          case 2 也执行
```

**建议练习：** 画箭头图，把 switch 的 case 画成一行标签，箭头从匹配的 case 指进去，然后一路往下画。

---

### 🟡 中度薄弱：`=` 和 `==` 的区分

**暴露问题：** 错题 2-9（以为 `i=j=10` 是语法错误）

**分析：** 用户知道 `=` 是赋值、`==` 是比较，但不知道**赋值表达式可以作为条件**。这和 Python 不同——Python 的 `if i = 10:` 会报语法错误，C 不会。

**需要牢记：**

```
C 语言中，赋值表达式有值（就是被赋的那个值）
i = 10  这个表达式的值是 10
10 非 0 → 条件为真
```

**建议：** 以后看到 `for` 或 `while` 条件里有单个 `=`，先想"这是赋值，值是右边的数"，而不是"这是语法错误"。

---

### 🟡 中度薄弱：`%` 取余与布尔判断

**暴露问题：** 疑惑 7（`i%2` 怎么判断奇偶）

**分析：** 用户需要看到 `== 0` 才能判断，不习惯 C 语言中"非 0 即真"的隐式转换。这是 Python 过来的常见习惯——Python 中 `if i % 2:` 也能用，但 C 的写法更常见。

**需要记住：**

```
i % 2 的结果只有 0 或 1
0 → 假 → 偶数
1 → 真 → 奇数
```
