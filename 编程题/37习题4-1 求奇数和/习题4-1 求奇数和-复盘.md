# 习题4-1 求奇数和 - 复盘

## 题目要求

计算给定的一系列正整数中奇数的和。输入在一行中给出一系列正整数，其间以空格分隔。当读到零或负整数时，表示输入结束，该数字不要处理。在一行中输出正整数序列中奇数的和。

输入样例：`8 7 4 3 70 5 6 101 -1`
输出样例：`116`

## 本题考点

- `for` 循环 + `break` 提前终止（哨兵值 sentinel 模式）
- `scanf` 循环读取不定数量输入（`%d` 自动跳过空白字符）
- 奇偶判断 `n % 2 == 1`（模运算）
- `if-else if` 多分支条件判断（利用短路的隐式排除）
- 累加求和模式（`s = s + n`）
- 变量初始化（`s = 0` 确保累加起点正确）

## 优化与拓展

### 优化 1：用 `while(1)` 替代固定上限的 `for` 循环

当前代码用 `for(i = 0; i < 100000; i++)` 设了一个 100000 的上限，虽然实际够用，但语义上不如 `while(1)` 清晰——因为循环次数由输入决定，而非固定上限：

```c
while (1) {
    scanf("%d", &n);
    if (n <= 0) break;
    if (n % 2 != 0) s += n;
}
```

### 优化 2：先判断终止条件，逻辑更清晰

当前代码的判断顺序是「先判断奇数 → 再判断终止」，这样需要 `else if`。更好的做法是「先判断终止 → 再判断奇数」，逻辑更直白：

```c
while (1) {
    scanf("%d", &n);
    if (n <= 0) break;      // 先判断哨兵
    if (n % 2 != 0) {       // 再判断奇数
        s += n;
    }
}
```

### 优化 3：奇偶判断用 `n % 2 != 0` 更通用

`n % 2 == 1` 只能判断正奇数，对于负奇数（如 `-3 % 2 == -1`）会漏判。虽然本题有 `n > 0` 保护，但养成用 `n % 2 != 0` 的习惯更安全、更通用。

### 两种写法对比

| 写法 | 当前代码 | 优化后 |
|------|----------|--------|
| 循环结构 | `for(i = 0; i < 100000; i++)` | `while (1)` |
| 判断顺序 | 先判奇数，`else if` 判终止 | 先判终止，`if` 判奇数 |
| 奇偶判断 | `n % 2 == 1` | `n % 2 != 0` |
| 结束方式 | `break` | `break` |
| 语义 | 暗含"最多 100000 次" | 明确"直到哨兵" |

## 关键知识点总结

1. **哨兵值终止输入**：用特殊值（0 或负数）作为输入结束标志，配合 `break` 跳出循环，是处理不定数量输入的经典模式。
2. **`scanf` 循环读取**：`%d` 自动跳过空格和换行，循环中反复 `scanf` 可以逐个读取空格分隔的整数。
3. **`n % 2 == 1` vs `n % 2 != 0`**：前者只适用于正奇数，后者对所有整数都正确。在 C 语言中，`-3 % 2 == -1`，所以判断奇偶用 `!= 0` 更安全。
4. **`if-else if` 的隐式排除**：`else if` 意味着"前面的条件都不成立"，可以利用这个特性简化条件判断。
5. **累加器初始化**：`s = 0` 是累加求和的起点，忘记初始化会导致结果不可预测。
6. **循环结构选择**：当循环次数由输入数据决定时，`while(1)` + `break` 比带固定上限的 `for` 语义更清晰。
