# 练习4-7 求e的近似值 - 复盘

## 题目要求

自然常数 e 可以用级数 `1 + 1/1! + 1/2! + ... + 1/n!` 来近似计算。给定非负整数 n（≤1000），求该级数的前 n+1 项和，保留小数点后八位。

## 本题考点

- **阶乘的递推计算**：`fact[i] = fact[i-1] * i`，利用前一项递推后一项，避免重复计算
- **浮点数除法 vs 整数除法**：`1.0 / fact` 而非 `1 / fact`，确保触发浮点除法
- **数组递推存储**：用数组存储每一项阶乘，方便后续使用
- **变量初始化**：`e = 1` 对应公式的第一项 `1`（即 `1/0!`），累加前必须初始化
- **`printf` 格式控制**：`%.8f` 保留八位小数
- **数组大小设计**：需要存 `arr[0]` 到 `arr[n]`，共 n+1 个元素，n ≤ 1000 时至少需要 1001 个
- **整数溢出意识**：阶乘增长极快，`int` 只能存到 12!，需要用 `double` 存储

## 错误记录

### 逻辑错误

#### 错误 1：阶乘构造错误
- **表现**：`arr[i] = (i * (i - o))`，由于 `o` 和 `i` 同步增长，`i - o` 始终为 0，arr[i] 永远为 0
- **原因**：不清楚阶乘的递推规律——每一项应该是 `前一项 × 当前数`，即 `arr[i] = arr[i-1] * i`
- **正确做法**：`arr[0] = 1; arr[i] = arr[i-1] * i;`

#### 错误 2：公式理解错误
- **表现**：`e = e + (1 + 1 / i)`，多了一个 `1 +`，且缺少阶乘
- **原因**：题目公式是 `1 + 1/1! + 1/2! + ...`，每一项是 `1/i!`，不是 `1 + 1/i`
- **正确做法**：`e = e + (1.0 / arr[i])`

#### 错误 3：整数除法陷阱
- **表现**：`1 / i` 当 `i > 1` 时结果始终为 0，导致累加无效
- **原因**：C 语言中两个 `int` 相除执行整数除法，自动舍去小数部分
- **正确做法**：`1.0 / arr[i]`，确保至少一个操作数是浮点数

### 语法错误

#### 错误 1：变量未初始化
- **表现**：`double e;` 后直接 `e = e + ...`，e 含有随机垃圾值
- **原因**：C 语言局部变量不会自动初始化为 0，与 Python 不同
- **正确做法**：`double e = 1;`（1 对应公式第一项 `1/0!`）

#### 错误 2：数组大小不足
- **表现**：`int arr[1000]` 当 n=1000 时访问 `arr[1000]` 越界
- **原因**：需要存 arr[0] 到 arr[n]，共 n+1 个元素
- **正确做法**：`double arr[1001];`

### 代码风格

#### 未使用变量
- **表现**：声明了 `int o` 但从未使用，编译产生警告
- **正确做法**：删除未使用的变量

## 优化与拓展

- **不用数组的写法**：只用一个变量 `fact` 累乘即可，不需存储全部阶乘：
  ```c
  double e = 1.0, fact = 1.0;
  for (int i = 1; i <= n; i++) {
      fact *= i;
      e += 1.0 / fact;
  }
  ```
- **阶乘用 `double` 存储的原因**：13! 已超出 `int` 范围（约 21 亿），n 最大 1000 时 `int` 必然溢出。`double` 虽对大阶乘有精度损失，但 `1/大阶乘` 本身就极小，不影响前 8 位小数结果
- **对比 Python**：Python 的整数没有溢出问题，`1/2` 自动得到浮点数，但 C 语言必须手动处理这两点

## 关键知识点总结

1. **阶乘递推**：`fact = fact * i`，从 1 开始乘，不需每次从头算
2. **浮点除法**：`1.0 / n` 而非 `1 / n`，这是 C 语言与 Python 的关键差异
3. **变量必须初始化**：C 局部变量不自动清零
4. **数组大小 = 最大下标 + 1**：存 arr[n] 需要至少 n+1 个元素
5. **阶乘溢出**：13! 已超 int 范围，大阶乘计算需用 `double` 或 `long long`
