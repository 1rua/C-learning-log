# 询问解答

当用户发送「询问」「ask」「为什么」「怎么回事」等关键词，或针对当前代码/题目提出疑问时，按以下流程解答。

## 触发关键词

- 询问
- ask
- 为什么
- 怎么回事
- 针对代码/题目的疑问

## 执行流程

### 1. 确定问题上下文

1. 根据当前对话上下文确定题目名称和当前进度
2. 如果用户的问题涉及具体代码，优先读取当前题目的代码文件
3. 如果用户的问题为通用知识点，直接进行讲解

### 2. 解答方式

根据问题类型选择解答策略：

- **代码相关问题**：定位到具体代码位置，解释原因并给出修改建议
- **知识点问题**：结合当前题目讲解相关 C 语言概念，必要时与 Python 对比
- **调试问题**：按照报错排查流程进行排查：
  - 先判断是编译错误还是运行错误
  - 拆开解释报错信息的关键部分
  - 解释最常见原因
  - 给出具体修改方法
  - 说明如何避免下次再犯
- **思路问题**：帮助用户拆解解题思路，理清逻辑

### 3. 解答原则

- **不要直接给完整答案**，优先引导用户自己理解
- 解释「为什么」，而不只是「怎么做」
- 结合用户已有的 Python 经验进行对比讲解
- 如果涉及代码修改，给出最小改动方案
- 不要只翻译英文报错，要解释深层原因

## 解答示例

### 报错讲解

对于报错信息：
```txt
error: expected ';' before 'return'
```

应解释为：
```md
这个错误通常不是 return 本身错了，而是 return 前一行可能少了分号。
C 编译器是在读到 return 时发现前面的语句还没正常结束，所以把错误位置报在 return 附近。
```

### 代码问题定位

```c
scanf("%d", a);
```

应说明：
```md
这里的问题是：scanf 读取普通变量时需要传入地址，所以应该写成 &a。
```

## 常见知识讲解方向

- `scanf` 为什么加 `&`
- 数组名为什么不需要加 `&`
- 字符串为什么要预留 `\0`
- `if (a = b)` 和 `if (a == b)` 的区别
- 数组越界为什么不报错但会出错
- 局部变量不初始化为什么有随机值
- C 语言与 Python 的差异对比
